# Obsi Sync — руководство по плагину

Obsi Sync связывает локальный vault Obsidian с сервером obsi-mcp. Плагин выполняет три независимые задачи:

1. Синхронизирует файлы с серверными vault'ами со сквозным шифрованием rclone.
2. Публикует разрешённые правилами заметки и вложения в AI Available для MCP-клиентов.
3. Применяет ожидающие изменения заметок, созданные MCP-клиентами.

Обычная синхронизация и AI Available имеют разную модель конфиденциальности: в первом случае сервер хранит шифротекст; во втором выбранные файлы передаются серверу **открытым текстом**. AI Available изначально выключен.

## Установка и обновление

Плагин поддерживает десктопный и мобильный Obsidian. Нужен адрес работающего сервера obsi-mcp. Подключиться можно по логину и паролю учетной записи, по access-токену или по выданному администратором device-токену.

Соберите плагин из каталога `plugin`:

```bash
npm install
npm run build
```

Поместите `main.js`, `manifest.json` и `styles.css` в `<ваш vault>/.obsidian/plugins/obsi-sync/`, затем включите Obsi Sync в Community plugins. При обновлении замените эти три файла и перезапустите или перезагрузите плагин. **Не удаляйте `data.json`:** в нём находятся локальные настройки, токены и пароли.

## Первое подключение

На новом устройстве откроется приветственное окно: короткий пошаговый мастер, после которого vault синхронизирован и готов к работе. Окно можно закрыть ссылкой «Не сейчас» и вернуться через команду «Obsi Sync: Настроить», вкладку «Обзор» в настройках плагина или щелчок по «Obsi: настройка» в строке статуса. На первом экране выберите один из двух вариантов.

### Подключиться к своему серверу

Путь из трёх-четырёх шагов, полоса вверху показывает текущий шаг. Кнопка «Назад» возвращает на предыдущий шаг без потери введённого, Enter нажимает основную кнопку.

1. **Подключение к серверу.** Введите адрес и выберите вход, регистрацию по приглашению или access-токен. Адрес можно вводить без схемы: для `localhost` и IP-адресов подставляется `http://`, для остальных `https://`; лишние `/` и вставленный по ошибке `/api/v1` убираются. Пароль учетной записи используется только для входа и не заменяет пароль шифрования.
2. **Выбор vault на сервере.** Отображаются доступные vault'ы; выбранный будет синхронизироваться со **всем** локальным vault Obsidian (корневое подключение). Пользователь с учётной записью может создать новый vault прямо в мастере, даже если у него уже есть другие. Ссылка «Сохраните подключение и выберите папки в настройках» сохраняет подключение без корневого подключения.
3. **Пароль шифрования.** Мастер заранее проверяет, есть ли данные в выбранном vault на сервере:
   - vault пуст — нужно придумать пароль и повторить его;
   - в vault уже есть заметки с другого устройства — нужно ввести тот же пароль; мастер сверяет его с данными на сервере и не пропустит дальше с неверным паролем;
   - если проверить не удалось (например, нет сети), пароль принимается без сверки, а первая синхронизация проверит его сама.

   Пароль хранится только на устройстве и не восстанавливается, его нужно использовать на всех устройствах этого серверного vault.
4. **Доступ ИИ.** Варианты: «Всё закрыто» (по умолчанию), «Только отмеченные заметки» (флажок `ai`) и «Все, кроме личных» (флажок `private`). Шаг пропускается, если сервер сообщает, что функции ИИ на нём выключены. Правила создаются только после успешной первой синхронизации; правила, уже пришедшие с другого устройства, не перезаписываются.

После «Завершить настройку» мастер сохраняет подключение и сразу запускает первую синхронизацию, показывая её ход. Окно можно закрыть кнопкой «Скрыть», синхронизация продолжится в фоне. По завершении появляется экран «Всё готово!» с подсказками: когда идёт автосинхронизация, где смотреть её состояние и как добавить другое устройство. Если первая синхронизация не удалась, мастер показывает ошибку и кнопку «Повторить»; настройки при этом уже сохранены, и плагин повторит попытку сам.

### Перенести настройку с другого устройства

На устройстве с нужными подключениями откройте вкладку «Устройства» и нажмите «Показать QR-код». На новом устройстве выберите в мастере «Перенести настройку с другого устройства» и снимите QR камерой, выберите изображение QR-кода или вставьте текст. Текст проверяется сразу при вводе: мастер показывает сервер и список vault'ов либо объясняет, что не так. Кнопка «Подключить это устройство» активна только для корректного набора. На исходном устройстве должны быть указаны адрес сервера, токен устройства и пароль каждого подключения. Экспорт поддерживает подключения с методом шифрования `rclone-base64`; если подключение использует другой или неподдерживаемый метод, сначала перенесите его данные вручную.

Импорт заменяет текущий адрес сервера, токен устройства и список подключений. При изменении подключения локальная история синхронизации затронутых vault'ов очищается; локальные файлы не удаляются. Новый токен не создаётся: на обоих устройствах будет использоваться один и тот же токен. Если устройство ещё не было настроено, мастер сразу запускает первую синхронизацию, как и при обычном подключении. Если на устройстве уже были свои настройки, мастер предупреждает о замене до импорта, а после него синхронизацию не запускает: проверьте подключения («Открыть подключённые vault'ы» ведёт на вкладку «Папки») и нажмите «Синхронизировать сейчас».

### Повторный запуск

Мастер подставляет сохранённые адрес, токен, а также vault и пароль корневого подключения. Пройдя путь подключения до конца, вы создадите или обновите корневое подключение; остальные подключения не меняются. Выход по ссылке «выбрать папки» корневое подключение не трогает.

## Строка статуса и команды

В строке статуса показаны значок и короткое состояние: «Obsi: настройка» (не настроено), «Синхронизировано 3 мин назад», «Синхронизация...» с ходом выполнения, «Синхронизация на паузе» или «Проблема синхронизации» (красным, подробности во всплывающей подсказке). До настройки щелчок открывает мастер, после настройки открывает меню: «Синхронизировать сейчас», «Приостановить/Возобновить синхронизацию», «Показать проблемы синхронизации» (если есть ошибки), «Добавить другое устройство» и «Настройки Obsi Sync». Строку можно скрыть на вкладке «Синхронизация» → «Внешний вид».

Команды Obsidian: «Синхронизировать сейчас», «Настроить» (мастер), «Открыть настройки», «Приостановить или возобновить синхронизацию», «Добавить другое устройство», а также «Опубликовать заметки для ИИ сейчас» и «Применить ожидающие правки MCP». Иконка синхронизации на левой панели запускает синк, а до настройки открывает мастер.

## Разделы настроек

Вкладки находятся в верхней части настроек плагина и закреплены при прокрутке; на узком экране у неактивных вкладок видны только значки.

| Вкладка | Назначение |
| --- | --- |
| **Обзор** | Состояние синхронизации, синк и пауза одной кнопкой, сводка по папкам, ИИ и устройствам, подключение к серверу. |
| **Синхронизация** | Когда синхронизировать, конфликты, защита от массовых изменений, корзина, строка статуса, дополнительные параметры. |
| **Папки** | Что и с какими серверными vault'ами синхронизируется, пароли, проверка пароля, схема папок без паролей. |
| **Устройства** | QR-код и текст для переноса настройки на другое устройство. |
| **ИИ** | Что могут видеть ИИ-ассистенты, свои правила, состояние публикации, правки от ИИ. |
| **Сервер** | Для каждого владельца аккаунта: личные токены устройств и MCP-клиентов. Для администратора дополнительно: учётные записи, приглашения, все vault'ы, смысловой поиск и все токены доступа. |

Интерфейс выбирает русский язык по языку Obsidian. Для остальных языков пока используется английский. Английский текст служит резервным, если в переводе нет строки.

### Обзор

Если плагин не настроен, вкладка предлагает два варианта, как в мастере: «Подключиться к своему серверу» и «Перенести настройку с другого устройства».

После настройки вверху находится карточка состояния: «Всё синхронизировано» со временем последней синхронизации и расписанием, «Синхронизация...» с полосой прогресса, «Синхронизация на паузе» или «Синхронизация требует внимания» со списком ошибок по каждой папке. Карточка обновляется на лету. Кнопки: «Синхронизировать сейчас» и «Пауза» (на паузе — «Возобновить синхронизацию»). Время последней синхронизации хранится только в памяти: после перезапуска Obsidian оно появится после первой синхронизации.

Ниже идёт раздел «Этот vault»: строки для каждой синхронизируемой папки с её состоянием, строка «Доступ ИИ» и строка «Другие устройства»; щелчок открывает соответствующую вкладку.

Карточка «Подключение» показывает адрес сервера и имя токена. «Проверить» проверяет соединение и объясняет ошибку так же, как мастер; если токен не типа `device`, появится предупреждение. «Изменить» открывает поля адреса и токена устройства; адрес нормализуется так же, как в мастере. Смена сервера или токена не затрагивает папки и пароли.

Внизу указана версия плагина и кнопка «Пройти настройку заново».

### Синхронизация

- **Синхронизация на этом устройстве** — главный переключатель; выключение ставит синк на паузу (то же, что «Пауза» на обзоре и в меню строки статуса). При возобновлении сразу запускается синхронизация.
- **Когда синхронизировать:** при сохранении заметки (через 1,5 секунды после последнего изменения), при запуске Obsidian и регулярно в фоне: никогда, каждую минуту, 5 (по умолчанию), 10, 15, 30 минут или каждый час. Все три способа включены по умолчанию.
- **Конфликты и защита:** если заметку изменили на двух устройствах, остаётся более новая (по умолчанию) или более длинная версия. «Останавливать синхронизацию с подозрительно большими изменениями» прерывает синк, который изменил бы или удалил больше 25, 50 (по умолчанию), 75 или 90% файлов; проверка действует при 10 и более файлах, вариант «Не останавливать» её отключает. Файлы, удалённые на другом устройстве, попадают в корзину Obsidian (папка `.trash`, по умолчанию) или в системную корзину.
- **Внешний вид:** показ состояния в строке статуса.
- **Дополнительно** (свёрнуто): синхронизация папки настроек Obsidian, задержка синка при запуске (5 секунд по умолчанию), число параллельных передач (3 по умолчанию).

Если значение было задано вручную в старой версии и не входит в список, оно сохраняется и показывается как дополнительный вариант.

Подключения обрабатываются по очереди, сначала более вложенные. Ошибка одного подключения не мешает попытке синхронизировать остальные. После синка плагин обновляет правила, проверяет ожидающие изменения MCP и запускает публикацию AI Available.

### Папки

Каждая синхронизируемая папка (подключение, mount) связывает папку локального vault с одним серверным vault и имеет отдельный пароль. Пустой путь означает весь vault. Папка, синхронизируемая отдельно, исключается из синхронизации всего vault: например, `Work` можно синхронизировать с отдельным серверным vault, не отправляя его файлы в основной.

Каждая папка показана карточкой: название («Весь vault» или путь), серверный vault и состояние («Синхронизировано 2 мин назад», «Ошибка», «Нужен пароль», «Нет vault на сервере», «На паузе», «Ждёт синхронизации»). Кнопка «Изменить» раскрывает редактор:

- «Папка в этом vault» с подсказками существующих папок;
- «Vault на сервере» — выбор из доступных токену; при смене vault история синхронизации старого и нового vault сбрасывается, чтобы следующий синк заново сравнил файлы;
- «Пароль шифрования» с кнопкой показа и кнопкой «Проверить», которая сверяет пароль с данными на сервере (или сообщает, что vault пуст);
- «Сбросить историю синхронизации» (с подтверждением; файлы не удаляются) и «Отключить» (с подтверждением; файлы остаются на устройстве и на сервере).

Кнопка «Синхронизировать весь vault» (или «Добавить папку», если весь vault уже подключён) добавляет подключение и сразу открывает его редактор. «Обновить список vault» перечитывает доступные серверные vault'ы.

Корневое подключение синхронизирует `.obsi/`, где лежит файл правил ИИ. Папка `.obsidian/` синхронизируется только при включении «Синхронизировать папку настроек Obsidian». При этом настройки плагинов, включая секреты других плагинов, попадут на сервер в зашифрованном виде. Собственный `data.json` Obsi Sync исключён из синка.

Поддерживается только метод `rclone-base64`. Старое подключение с OpenSSL сохраняется в конфигурации с состоянием «Неподдерживаемое шифрование» и блокирует синхронизацию до **ручного переноса данных**. Плагин не меняет метод шифрования автоматически.

В свёрнутом блоке «Передать схему папок без паролей» можно скопировать схему (адрес сервера, пути, ID и имена vault'ов, метод шифрования; **пароли и токены не экспортируются**) и импортировать её на другом устройстве. Импорт добавляет только отсутствующие папки, пароли нужно ввести отдельно.

### Устройства

Вкладка объясняет три шага переноса: установить плагин на новом устройстве, выбрать в мастере «Перенести настройку с другого устройства», отсканировать QR-код или вставить текст. QR-код по умолчанию скрыт: сначала показывается предупреждение, затем кнопка «Показать QR-код». После показа доступны «Скопировать текст настройки», «Сохранить изображение QR», «Скрыть» и свёрнутый блок «Показать текст настройки». QR снова скрывается при переходе на другую вкладку и при закрытии настроек.

Набор (device-adder) — версионированный JSON с адресом сервера, существующим токеном устройства и всеми подключениями: путями, ID и именами серверных vault'ов, паролями и методом шифрования. QR содержит тот же набор, что и текст; при длинном списке подключений QR может считываться ненадёжно, тогда используйте текст. Набор доступен, когда настроены адрес сервера, токен, хотя бы одно подключение и пароли подключений с методом `rclone-base64`; иначе вкладка объясняет, чего не хватает.

Device-adder — секретный материал: текст и QR позволяют читать и менять заметки. Если исходное устройство вошло в аккаунт по имени и паролю, набор содержит токен входа, с которым можно также выпускать новые токены доступа. Передавайте набор только своим устройствам и удаляйте скопированный текст или сохранённое изображение после переноса. Admin-токен и прочие настройки в набор не входят. Оба устройства используют один токен; чтобы потом можно было отозвать доступ у одного устройства, войдите в аккаунт на вкладке «Сервер» и создайте отдельный токен.

### ИИ: что могут видеть ассистенты

Публикация (AI Available) передаёт разрешённые заметки на сервер **открытым текстом**, чтобы MCP-клиенты могли их читать и предлагать правки. Она работает, когда на устройстве включён доступ ИИ, существует корневое подключение и файл `.obsi/ai-rules.json` успешно разобран. Без корневого подключения вкладка показывает предупреждение.

Раздел «Что может видеть ИИ?» — четыре варианта:

- **Ничего** — доступ ИИ выключен на этом устройстве. При выключении можно выбрать «Выключить» или «Выключить и удалить открытые» (удаляет уже опубликованные данные с сервера).
- **Только отмеченные заметки** — правило: открыты заметки с `ai: true`; новые пустые заметки получают `ai: false`.
- **Все, кроме личных** — открыто всё, кроме заметок с `private: true`; новые пустые заметки получают `private: false`.
- **Свои правила** — редактор правил (см. ниже).

Правила хранятся в `.obsi/ai-rules.json` и синхронизируются, поэтому действуют на всех устройствах vault. Если текущие правила отличаются от выбранного варианта, плагин спросит подтверждение перед заменой. Включение доступа ИИ — настройка конкретного устройства.

Когда доступ включён, карточка «Доступ ИИ» показывает результат последней публикации (сколько файлов открыто и убрано, ошибки или причину, по которой публикация не выполнялась) и кнопки «Обновить сейчас» и «Применить правки ИИ».

Редактор своих правил записан фразами: «Заметки, к которым не подходит ни одно правило, скрыты от ИИ / открыты для ИИ», затем строки вида «Открыть / Скрыть заметки в папке …» и «Открыть / Скрыть заметки, где свойство … отмечено / не отмечено / существует / равно … / содержит …». Для правил «отмечено/не отмечено» есть флажок «Добавлять флажок в новые заметки». Изменения копятся в черновике: внизу появляется панель «Есть несохранённые изменения» с кнопками «Отменить» и «Сохранить правила». Несохранённый черновик сбрасывается при закрытии настроек.

В свёрнутом блоке «Дополнительно»: максимальный размер файла для ИИ (25 МБ по умолчанию), как часто проверять правки от ИИ (каждые 2 минуты по умолчанию; «Только после синхронизации» отключает таймер) и «Удалить открытые для ИИ заметки с сервера».

Формат файла правил:

Пример правил:

```json
{
  "version": 1,
  "mode": "deny_by_default",
  "rules": [
    { "id": "r1", "type": "folder", "effect": "include", "path": "Projects" },
    { "id": "r2", "type": "folder", "effect": "exclude", "path": "Projects/Private" },
    { "id": "r3", "type": "property", "effect": "include", "key": "ai", "op": "equals", "value": true, "addToNewNotes": true }
  ]
}
```

- `mode` решает судьбу заметки, если ни одно правило не совпало: `deny_by_default` или `allow_by_default`.
- `folder` сопоставляется с самой папкой и всем содержимым. Пустой `path` означает весь локальный vault.
- `property` проверяет frontmatter заметки: операции `exists`, `equals`, `contains`. Для `tags` учитываются также теги в тексте; вложенные теги совпадают с родительским.
- Если совпало исключающее правило, оно имеет приоритет над включающим. Неизвестное исключающее правило блокирует публикацию соответствующих файлов.
- Вложения публикуются, если на них ссылается хотя бы одна разрешённая заметка и их не исключает правило папки. Правила свойств действуют только на заметки.
- `addToNewNotes: true` для правила со значением `true` или `false` добавляет свойство в новую пустую заметку в состоянии, противоположном значению правила. Заметки, созданные сразу с текстом шаблоном или через MCP, не изменяются.

Публикация выполняется после изменений файлов и правил, после синхронизации и при запуске плагина; изменения группируются с задержкой (5 секунд по умолчанию).

### Изменения от MCP

Клиент MCP может создать ожидающее изменение заметки через `write_note`. Плагин проверяет очередь после синхронизации и по таймеру. Изменение применяется только к `.md` в соответствующем подключении, если путь безопасен, правило AI разрешает заметку до и после правки, а версия локального файла не конфликтует с базовой версией изменения. Плагин сообщает серверу результат `applied`, `conflict` или `rejected`.

### Сервер: личные токены и администрирование

В разделе «Мои токены доступа» пользователь, вошедший в аккаунт по имени и паролю, может создать токен типа «Устройство» для другого Obsidian или «ИИ-ассистент» для MCP-клиента. Выберите название и права по каждому доступному vault; для единственного vault права устройства отмечены сразу, а у MCP-токена право предлагать правки (`write`) по умолчанию выключено. Токен показывается один раз — скопируйте его сразу. Ни один личный токен не может получить права на чужой vault или выпускать новые токены. В списке видны выданные токены, их права и последнее использование; «Отозвать» отключает токен немедленно. Для управления личными токенами admin-токен не нужен.

Если плагин подключён с уже выданным access-токеном, раздел предложит войти в учётную запись через мастер настройки: сам access-токен не может выпускать новые токены. При недоступном сервере раздел показывает ошибку и кнопку повтора.

Вкладка для того, кто администрирует сервер. Её можно найти по названию «Сервер» в настройках Obsi Sync. Введите admin-токен и нажмите «Подключиться»: плагин загрузит учётные записи, vault'ы, приглашения, токены и настройки смыслового поиска (при следующих открытиях вкладки загрузка идёт автоматически). Admin-токен хранится только на устройстве в `data.json`.

- **Учётные записи:** в разделе «Учётные записи» показаны зарегистрированные пользователи, число их собственных vault'ов и всех выпущенных для аккаунта токенов (включая отозванные). Здесь же создаются приглашения: введите имя, нажмите «Создать приглашение» и передайте одноразовый код пользователю. В мастере он выбирает «Создать аккаунт» и вводит код, имя пользователя и пароль. Обычный вход выполняется по имени пользователя и паролю.

- **Vault'ы:** список с датой создания и переключателем смыслового поиска (RAG); создание нового vault по названию.
- **Токены доступа:** у каждого токена видны тип («Устройство», «ИИ-ассистент», «Admin»), права по vault'ам с их именами и время последнего использования; отозванные показаны бледно внизу. «Отозвать» требует подтверждения. «Новый токен» открывает окно: название, тип карточкой, права по каждому vault флажками с подписями (для единственного vault права включены сразу). Созданный токен показывается один раз с кнопкой «Скопировать».
- **Приглашения:** в разделе «Учётные записи» задайте имя и создайте одноразовый код регистрации. Код показывается только в окне создания, его нужно сразу передать пользователю. В списке видны имя, дата и состояние использования, без кода.
- **Создание vault пользователем:** учётная запись может создать собственный vault из мастера подключения независимо от числа уже созданных vault'ов.
- **Смысловой поиск:** адрес OpenAI-совместимого API, ключ и модель заполняются текущими значениями сервера; ключ приходит замаскированным, и если его не менять, он не отправляется. Если сервер сообщает состояние индекса, видно число готовых и ожидающих фрагментов или последнюю ошибку. Смена адреса или модели перестраивает индексы всех vault'ов.

## Инструменты разработчика

На вкладке «Обзор» семь раз нажмите на версию плагина внизу. До закрытия окна настроек появится вкладка **Dev**: «Показать экран приветствия» снова открывает мастер, «Показать приветствие при следующем запуске» сбрасывает признак первого входа (окно откроется при запуске, если синхронизация не настроена). Само открытие мастера ничего не сбрасывает; если пройти его до конца, могут измениться подключение и корневое подключение (см. «Повторный запуск»).

## Если что-то не работает

| Ситуация | Что проверить |
| --- | --- |
| Синхронизация не запускается | Не стоит ли синхронизация на паузе (строка статуса, вкладка «Обзор»), указаны ли адрес сервера, токен устройства, серверный vault и пароль на вкладке «Папки». |
| Сервер отклоняет запрос | Действует ли токен `kind=device` и есть ли права `read`/`write` на нужный vault. Кнопка «Проверить» в карточке «Подключение» на вкладке «Обзор» показывает имя токена и доступные vault'ы. |
| Ошибка метода шифрования | Подключение использовало OpenSSL или неизвестный метод. Нужен ручной перенос данных на rclone. |
| Device-adder не создаётся или не импортируется | Проверьте адрес сервера, токен, наличие подключений и паролей, поддержку метода `rclone-base64` и целостность полного JSON/QR. Версия формата должна поддерживаться плагином. Если QR не распознаётся, используйте копирование текста; если сервер недоступен или токен не имеет прав, проверьте соединение отдельно. |
| Неверный пароль | Используйте пароль, которым зашифрованы данные этого серверного vault; кнопка «Проверить» у пароля на вкладке «Папки» сверит его с сервером. Сервер пароль не хранит и восстановить не может. |
| AI Available пуст | Карточка «Доступ ИИ» на вкладке «ИИ» показывает причину: выключен доступ, нет корневого подключения, нет правил или в них ошибки. Проверьте также, что правила совпадают с нужными заметками. |
| Изменение MCP не применилось | Проверьте права `write`, правила AI, допустимость пути и базовую версию заметки; конфликт не перезаписывает локальный файл. |

## Разработка и поддержка документации

Основные точки входа: `src/main.ts` (события Obsidian), `src/ui/` (настройки и первый вход), `src/settings.ts` (настройки и подключения), `src/syncManager.ts` и `src/sync/` (синк), `src/ai/` (правила, публикация, применение правок), `src/i18n.ts` и `src/locales/ru.ts` (локализация). Контракт сервера описан отдельно в [API.md](API.md), обзор кода — в [CODEMAP.md](CODEMAP.md).

```bash
npm run typecheck
npm test
npm run build
```

Для сквозного теста с сервером: `OBSI_SERVER_DIR=/path/to/server npm run e2e`. Проектное правило обновления документации при изменении фич закреплено в `AGENTS.md` и skill `skills/obsi-plugin-docs/SKILL.md`.
