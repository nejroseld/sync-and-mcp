# Obsi Sync — руководство по плагину

Obsi Sync связывает локальный vault Obsidian с сервером obsi-mcp. Плагин выполняет три независимые задачи:

1. Синхронизирует файлы с серверными vault'ами со сквозным шифрованием rclone.
2. Публикует разрешённые правилами заметки и вложения в AI Available для MCP-клиентов.
3. Применяет ожидающие изменения заметок, созданные MCP-клиентами.

Обычная синхронизация и AI Available имеют разную модель конфиденциальности: в первом случае сервер хранит шифротекст; во втором выбранные файлы передаются серверу **открытым текстом**. AI Available изначально выключен.

## Установка и обновление

Плагин поддерживает десктопный и мобильный Obsidian. Нужны адрес работающего сервера obsi-mcp и токен устройства (`kind=device`) с правами `read` и `write` на нужные серверные vault'ы.

Соберите плагин из каталога `plugin`:

```bash
npm install
npm run build
```

Поместите `main.js`, `manifest.json` и `styles.css` в `<ваш vault>/.obsidian/plugins/obsi-sync/`, затем включите Obsi Sync в Community plugins. При обновлении замените эти три файла и перезапустите или перезагрузите плагин. **Не удаляйте `data.json`:** в нём находятся локальные настройки, токены и пароли.

## Первое подключение

На новом устройстве откроется приветственное окно. Его можно закрыть кнопкой «Не сейчас» и вернуться через команду «Obsi Sync: Настроить» или кнопку настройки плагина.

1. Нажмите «Подключить сервер», введите адрес сервера и токен устройства, затем проверьте подключение.
2. Выберите доступный серверный vault.
3. Решите, подключать ли **весь локальный vault Obsidian**. При включении этой опции укажите пароль шифрования и нажмите «Сохранить и синхронизировать». Используйте тот же пароль на остальных устройствах этого серверного vault.
4. Если автомаунт не нужен, нажмите «Сохранить подключение». Файлы не синхронизируются, пока вы не добавите подключение в настройках.
5. По желанию выберите режим доступа для ИИ. Он включится только после успешной первой синхронизации; правила, уже пришедшие с другого устройства, не перезаписываются.

Чтобы перенести готовую настройку на другое устройство, на устройстве с нужными подключениями откройте верхнюю вкладку «Добавить другое устройство»: текст и QR появятся автоматически. Скопируйте текст или покажите QR-код; на новом устройстве в приветственном окне нажмите «Добавить с другого устройства», вставьте текст либо выберите изображение QR-кода или снимите его камерой. Проверьте список vault'ов и нажмите «Импортировать подключение», после чего запустите синхронизацию вручную. На исходном устройстве должны быть указаны адрес сервера, токен устройства и пароль каждого подключения. Экспорт поддерживает подключения с методом шифрования `rclone-base64`; если подключение использует другой или неподдерживаемый метод, сначала перенесите его данные вручную.

Импорт заменяет текущий адрес сервера, токен устройства и список подключений после подтверждения. При изменении подключения локальная история синхронизации затронутых vault'ов очищается; локальные файлы не удаляются. Он не создаёт новый токен: на обоих устройствах будет использоваться один и тот же токен. После импорта проверьте подключения и вручную начните синхронизацию. Если на новом устройстве уже есть настройки подключения, заранее сохраните нужные данные: подтверждённый импорт заменит их.

При повторном открытии приветственного окна существующее корневое подключение сохраняется, пока вы явно не включите его создание и не сохраните новые параметры.

## Разделы настроек

Вкладки находятся в верхней части настроек плагина. Переключение вкладок не сбрасывает значения полей.

| Вкладка | Назначение |
| --- | --- |
| **Подключение** | Адрес сервера, токен устройства, проверка соединения, версия плагина. |
| **Синхронизация** | Автозапуск, синк при сохранении, интервал, конфликты, защита от массовых изменений и ручной запуск. |
| **Подключённые vault'ы** | Соответствие локальных папок серверным vault'ам, пароли, экспорт и импорт схемы подключений. |
| **Добавить другое устройство** | Показывает текст device-adder и QR для переноса подключения при открытии вкладки. |
| **ИИ** | Публикация AI Available, правила доступа, размер файлов, применение изменений MCP. |
| **Администрирование** | Серверные vault'ы, RAG, эмбеддинги и токены; нужен отдельный admin-токен. |

Интерфейс выбирает русский язык по языку Obsidian. Для остальных языков пока используется английский. Английский текст служит резервным, если в переводе нет строки.

### Синхронизация

`Sync enabled`, `Sync on save` и `Sync on startup` включены по умолчанию. Синк при сохранении реагирует на создание и изменение файлов, которые принадлежат одному из подключений, с задержкой 1,5 секунды для объединения серии событий. Периодический синк запускается каждые 5 минут по умолчанию; значение `0` его выключает. Ручной запуск доступен кнопкой в настройках, иконкой на ленте и командой Obsidian.

Подключения обрабатываются по очереди, сначала более вложенные. Ошибка одного подключения не мешает попытке синхронизировать остальные. После синка плагин обновляет правила, проверяет ожидающие изменения MCP и запускает публикацию AI Available.

При конфликте можно оставить более новый или больший файл. По умолчанию используется «более новый». `Safety limit` (50% по умолчанию) останавливает синк, который изменил бы или удалил слишком большую долю файлов; проверка действует при 10 и более файлах, `-1` отключает её. Удаления по умолчанию отправляются в корзину Obsidian.

### Подключения (mounts)

Каждое подключение связывает одну папку локального vault с одним серверным vault и имеет отдельный пароль. Пустой путь означает корень локального vault. Вложенное подключение исключается из родительского: например, `Work` можно синхронизировать отдельно, не отправляя его файлы в корневой серверный vault.

Корневое подключение синхронизирует `.obsi/`, где лежит файл правил ИИ. Папка `.obsidian/` синхронизируется только при включении «Синхронизировать папку настроек Obsidian». При этом настройки плагинов, включая секреты других плагинов, попадут на сервер в зашифрованном виде. Собственный `data.json` Obsi Sync исключён из синка.

Поддерживается только метод `rclone-base64`. Старое подключение с OpenSSL сохраняется в конфигурации, но блокирует синхронизацию до **ручного переноса данных**. Плагин не меняет метод шифрования автоматически: смена строки метода без переноса удалённого хранилища не расшифрует старые данные.

Обычный экспорт схемы подключений содержит адрес сервера, пути, ID и имена vault'ов, метод шифрования; **пароли и токены не экспортируются**. После импорта введите пароли отдельно. Это подходит для переноса структуры без секретов.

Для полного переноса на другое устройство откройте отдельную верхнюю вкладку «Добавить другое устройство». При открытии вкладки автоматически появляются версионированный JSON и QR с адресом сервера, существующим токеном устройства и всеми подключениями: локальными путями, ID и именами серверных vault'ов, паролями и методом шифрования. При уходе с вкладки они убираются из интерфейса, при возвращении создаются заново из текущих настроек. Набор можно скопировать как текст или сохранить/показать как QR-код. На экране приветствия нового устройства его можно вставить текстом, выбрать QR-изображение через файловый выбор или снять QR камерой. QR содержит тот же секретный набор, что и текст; длинный список подключений или пароли могут сделать QR слишком плотным для надёжного считывания — в таком случае используйте текст. Экспорт доступен, когда настроены адрес сервера, токен, хотя бы одно подключение и пароли подключений; текущая версия принимает метод `rclone-base64`.

Устройство-источник должно быть уже подключено к серверу и иметь настроенные подключения с паролями. На новом устройстве импорт требует подтверждения и заменяет адрес сервера, токен устройства и список подключений. Он не создаёт серверный токен; оба устройства используют переданный токен. После импорта плагин сохраняет конфигурацию, но не запускает синхронизацию автоматически — проверьте список подключений и начните её вручную.

Device-adder — секретный материал: текст и QR содержат действующий токен и пароли шифрования. Передавайте их только доверенным способом, не оставляйте QR на виду и удалите скопированный текст или сохранённое изображение после переноса. Admin-токен и прочие настройки плагина в набор не входят. Кнопка «Сбросить историю синхронизации» очищает локальную историю выбранного серверного vault; она не удаляет файлы.

### AI Available и правила доступа

Публикация работает только когда включён AI Available, существует корневое подключение и файл `.obsi/ai-rules.json` успешно разобран. При ошибках в файле правил публикация не выполняется. Отключение AI Available останавливает публикацию; уже опубликованные данные удаляются отдельной кнопкой «Удалить опубликованные данные».

Пример правил:

```json
{
  "version": 1,
  "mode": "deny_by_default",
  "rules": [
    { "id": "r1", "type": "folder", "effect": "include", "path": "Projects" },
    { "id": "r2", "type": "folder", "effect": "exclude", "path": "Projects/Private" },
    { "id": "r3", "type": "property", "effect": "include", "key": "ai", "op": "equals", "value": true, "addToNewNotes": true }
  ]
}
```

- `mode` решает судьбу заметки, если ни одно правило не совпало: `deny_by_default` или `allow_by_default`.
- `folder` сопоставляется с самой папкой и всем содержимым. Пустой `path` означает весь локальный vault.
- `property` проверяет frontmatter заметки: операции `exists`, `equals`, `contains`. Для `tags` учитываются также теги в тексте; вложенные теги совпадают с родительским.
- Если совпало исключающее правило, оно имеет приоритет над включающим. Неизвестное исключающее правило блокирует публикацию соответствующих файлов.
- Вложения публикуются, если на них ссылается хотя бы одна разрешённая заметка и их не исключает правило папки. Правила свойств действуют только на заметки.
- `addToNewNotes: true` для правила со значением `true` или `false` добавляет свойство в новую пустую заметку в состоянии, противоположном значению правила. Заметки, созданные сразу с текстом шаблоном или через MCP, не изменяются.

Кнопка создания правил начинает с безопасного варианта: разрешены только заметки с отмеченным свойством `ai`; новые пустые заметки получают `ai: false`. В приветственном окне можно также выбрать разрешение всех заметок, кроме помеченных `private`.

Публикация выполняется после изменений файлов и правил, после синхронизации и при запуске плагина; изменения группируются с задержкой (5 секунд по умолчанию). Максимальный размер публикуемого файла — 25 МБ по умолчанию.

### Изменения от MCP

Клиент MCP может создать ожидающее изменение заметки через `write_note`. Плагин проверяет очередь после синхронизации и по таймеру (каждые 2 минуты по умолчанию). Изменение применяется только к `.md` в соответствующем подключении, если путь безопасен, правило AI разрешает заметку до и после правки, а версия локального файла не конфликтует с базовой версией изменения. Плагин сообщает серверу результат `applied`, `conflict` или `rejected`. Значение интервала `0` оставляет проверку после синхронизации и по команде.

### Администрирование

Вкладка открыта сразу, без внутреннего раскрывающегося блока. Admin-токен хранится на устройстве в `data.json` и используется только здесь. Можно создать серверный vault, включить RAG, указать совместимый с OpenAI API для эмбеддингов, создать токены `device`, `mcp`, `admin` и отозвать токены. Полный текст нового токена показывается один раз. Смена модели или адреса эмбеддингов перестраивает индекс на сервере.

## Отладка приветственного окна

В разделе **Подключение** семь раз нажмите кнопку с версией плагина. На время текущей сессии настроек появится вкладка **Dev / Отладка**. Кнопка **Show welcome screen / Показать экран приветствия** снова открывает тот же сценарий первого входа. Само открытие не сбрасывает подключение; сохранение в окне может изменить его и конфигурацию подключений.

## Если что-то не работает

| Ситуация | Что проверить |
| --- | --- |
| Синхронизация не запускается | Включён ли `Sync enabled`, указаны ли адрес сервера, токен устройства, серверный vault и пароль подключения. |
| Сервер отклоняет запрос | Действует ли токен `kind=device` и есть ли права `read`/`write` на нужный vault. Кнопка проверки подключения показывает доступные vault'ы и права. |
| Ошибка метода шифрования | Подключение использовало OpenSSL или неизвестный метод. Нужен ручной перенос данных на rclone. |
| Device-adder не создаётся или не импортируется | Проверьте адрес сервера, токен, наличие подключений и паролей, поддержку метода `rclone-base64` и целостность полного JSON/QR. Версия формата должна поддерживаться плагином. Если QR не распознаётся, используйте копирование текста; если сервер недоступен или токен не имеет прав, проверьте соединение отдельно. |
| Неверный пароль | Используйте пароль, которым зашифрованы данные этого серверного vault. Сервер его не хранит и восстановить не может. |
| AI Available пуст | Проверьте включение функции, корневое подключение, валидность `.obsi/ai-rules.json` и совпадение правил с нужными заметками. |
| Изменение MCP не применилось | Проверьте права `write`, правила AI, допустимость пути и базовую версию заметки; конфликт не перезаписывает локальный файл. |

## Разработка и поддержка документации

Основные точки входа: `src/main.ts` (события Obsidian), `src/ui/` (настройки и первый вход), `src/settings.ts` (настройки и подключения), `src/syncManager.ts` и `src/sync/` (синк), `src/ai/` (правила, публикация, применение правок), `src/i18n.ts` и `src/locales/ru.ts` (локализация). Контракт сервера описан отдельно в [API.md](API.md), обзор кода — в [CODEMAP.md](CODEMAP.md).

```bash
npm run typecheck
npm test
npm run build
```

Для сквозного теста с сервером: `OBSI_SERVER_DIR=/path/to/server npm run e2e`. Проектное правило обновления документации при изменении фич закреплено в `AGENTS.md` и skill `skills/obsi-plugin-docs/SKILL.md`.
